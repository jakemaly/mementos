# Deep Research Trace Redesign

## Problem Statement

The active Deep Research workspace currently spreads one research run across four equally prominent panes. The route, brief and sketch, observability timeline, and evidence register are all useful, but the composition makes the process feel like a dashboard rather than a legible journey from a question to selected evidence.

The owner needs to understand, at a glance:

- which question is being followed;
- whether the brief and sketch have been created;
- which searches are planned, running, empty, or failed;
- how the supervisor is moving through iterations;
- when evidence has been ranked; and
- when the final source list is ready to import.

The current event stream already contains the facts needed to tell that story. The problem is presentation and projection, not research behavior. The redesign must make the route visually primary without changing the existing SSE contract, source ranking, source selection, ingestion behavior, cancellation semantics, or collection workflow.

## Solution

Replace the active four-pane Deep Research workspace with one scrollable, fullscreen-in-the-content-area trace surface. Keep the compact global navigation shell, but let the trace own the research content area.

The surface begins with the submitted query centered at the top as stable, wrapped calling-card lettering generated by the existing calling-card renderer. A semantic text equivalent remains available for accessibility, selection, copying, and overflow handling. A compact utility strip retains status, elapsed time, Cancel, and New Research.

The process is rendered as a vertical zig-zag route:

1. A visible pending **Brief + Sketch** milestone appears below the query. Its two artifact rows resolve independently to **Brief created ✓** and **Sketch created ✓** and open anchored detail popovers.
2. A compact central-spine supervisor checkpoint marks each iteration.
3. Each checkpoint owns a fan-out of one pending node per planned query-result batch. Each source node resolves to a new-unique-source count, zero sources, or a failed-search outcome and includes compact tool/query context.
4. A later supervisor checkpoint may own another fan-out. Newly introduced queries append in event order without reflowing already-rendered history.
5. A compact **Evidence ranked** checkpoint precedes the final **Ingest Sources** node.
6. The final node remains visibly pending and locked until the ranked, deduplicated result arrives. It then opens a focus-managed modal containing the existing full source checklist and import controls.

Nodes use original angular black-card CSS geometry with red accents. Deterministic SVG paths draw jagged black connections behind the semantic route. The active segment may use a restrained red accent; failure and success are always communicated with text or markers as well. Completed connections draw on as work completes. Reduced-motion mode shows the final state without movement.

On narrow screens the fan-out collapses into a single vertical route. The page remains vertically scrollable, with no horizontal trace canvas, pan, zoom, or minimap.

## User Stories

1. As the owner, I want the submitted research query to remain visible throughout the run, so that I always know which question the route represents.
2. As the owner, I want the query displayed as distinctive calling-card lettering, so that the research surface has a clear visual identity.
3. As the owner, I want the query to wrap across a small number of readable lines, so that long questions do not become tiny or overflow the viewport.
4. As the owner, I want the visible query artwork to remain stable while live events arrive, so that unrelated progress updates do not make the header jump.
5. As the owner, I want a semantic text equivalent of the calling-card query, so that I can read, select, copy, and understand it with assistive technology.
6. As the owner, I want to see the current research status and elapsed time in a compact utility area, so that operational information remains available without becoming a process node.
7. As the owner, I want to cancel an active run from the trace surface, so that I can stop a research request without hunting through the navigation.
8. As the owner, I want New Research to remain available after a run, so that I can return to a clean composer without retaining stale route state.
9. As the owner, I want the Brief + Sketch milestone visible while it is pending, so that I can tell the run has started even before the model responds.
10. As the owner, I want Brief created and Sketch created to resolve independently, so that partial progress is visible rather than hidden behind one generic loading state.
11. As the owner, I want to click the Brief created row, so that I can inspect the scoped research brief without leaving the route.
12. As the owner, I want to click the Sketch created row, so that I can inspect concepts, discriminative terms, patterns, preferred domains, and search context without leaving the route.
13. As the owner, I want artifact details in a compact anchored popover, so that the detail remains spatially connected to the milestone.
14. As the owner, I want long artifact details to scroll inside their popover, so that the route does not shift unpredictably.
15. As the owner, I want artifact popovers to close with an explicit control, Escape, or an outside click, so that I can return to the route through familiar interactions.
16. As the owner, I want artifact popovers to become a bottom-sheet-like dialog on narrow screens when necessary, so that content is not clipped or squeezed.
17. As the owner, I want each supervisor iteration represented by a compact checkpoint, so that I can understand that the research route is making repeated decisions without reading every raw event.
18. As the owner, I want checkpoints on the central spine, so that shared decisions remain visually distinct from individual search branches.
19. As the owner, I want each checkpoint to own its query fan-out, so that the route reflects which searches belong to which iteration.
20. As the owner, I want planned query batches to appear as pending nodes once the plan is known, so that I can see the intended route before results arrive.
21. As the owner, I want one source node per query-result batch, so that separate searches do not collapse into an untraceable aggregate.
22. As the owner, I want a source node to show its tool and shortened query alongside the count, so that I can identify the batch without opening another detail surface.
23. As the owner, I want source nodes to remain display-only, so that the route does not accumulate unnecessary popovers or tab stops.
24. As the owner, I want a source node to count newly added canonical URLs, so that duplicate results do not inflate the apparent evidence gained from a search.
25. As the owner, I want a zero-result batch to remain visible, so that I can distinguish an executed empty search from a search that never ran.
26. As the owner, I want a failed search batch to remain visible with an explicit failure state, so that the route is honest about incomplete evidence.
27. As the owner, I want later supervisor passes to append newly introduced queries in event order, so that completed history does not move while the route is live.
28. As the owner, I want completed route nodes and connections to remain visible while later work continues, so that the process accumulates into an understandable trace.
29. As the owner, I want active connections to draw on as their work completes, so that progress is visually legible without continuous distracting animation.
30. As the owner, I want the active route accent to use red while the base route remains black, so that the visual hierarchy stays restrained and the current work is easy to locate.
31. As the owner, I want the route to remain understandable when motion is reduced, so that disabling animation does not remove process information.
32. As the owner, I want an Evidence ranked checkpoint before ingestion, so that I know the final list is the ranked and deduplicated evidence set.
33. As the owner, I want the Ingest Sources node to remain visibly pending while ranking is incomplete, so that I do not mistake accumulated live results for the final evidence set.
34. As the owner, I want the Ingest Sources node to unlock only after the final ranked result arrives, so that the existing evidence contract is preserved.
35. As the owner, I want the final source list to open in a full checklist modal, so that I can review evidence without losing the route surface.
36. As the owner, I want the source modal to contain the existing numbered source rows, links, snippets, select-all behavior, selected count, and import action, so that the redesign does not remove useful evidence controls.
37. As the owner, I want newly discovered final sources to follow the existing default-selection behavior, so that the redesign does not change how evidence becomes selected.
38. As the owner, I want explicit deselections to survive source reconciliation, so that ranking updates do not silently reselect evidence I rejected.
39. As the owner, I want the source modal to trap focus while open and return focus to Ingest Sources when it closes, so that keyboard use remains predictable.
40. As the owner, I want a successful import to close the modal and mark the final node as imported, so that the route communicates completion without discarding the evidence trail.
41. As the owner, I want partial import failures to remain visible and retryable, so that one failed source does not erase successful imports or hide the remaining work.
42. As the owner, I want total import failure to remain explicit, so that I can distinguish an ingestion problem from a successful research run.
43. As the owner, I want a failed or timed-out research run to retain its completed and pending route nodes, so that I can see what happened before the failure.
44. As the owner, I want ingestion to remain locked when ranking did not complete, so that partial unranked evidence is not presented as the final result.
45. As the owner, I want the existing error message and New Research action to remain available after failure, so that I have a clear recovery path.
46. As the owner, I want Cancel to abort and reset the run as it does today, so that a cancelled run does not leave stale state or a misleading retained history.
47. As the owner, I want the compact global navigation shell to remain available, so that the fullscreen trace does not trap me inside Deep Research.
48. As the owner, I want the idle query composer to remain unchanged, so that this redesign stays focused on the post-submit research experience.
49. As the owner, I want the route to scroll vertically when there are many batches, so that every event remains available without arbitrary node caps or pan/zoom controls.
50. As the owner, I want the desktop route to use a vertical zig-zag composition, so that the process feels stylized while remaining easy to follow.
51. As the owner, I want the mobile route to collapse into a readable vertical sequence, so that narrow screens do not require horizontal scrolling.
52. As the owner, I want the route order to remain the process order in the DOM, so that visual geometry does not undermine keyboard or screen-reader comprehension.
53. As the owner, I want only actual actions to be keyboard tabbable, so that display-only source nodes and decorative connectors do not create a long, noisy focus path.

55. As the owner, I want the angular visual language to use existing project assets and typography only, so that the redesign does not add licensing risk, downloaded reference artwork, or a new dependency.
56. As the owner, I want the existing research stream, ranking behavior, collection selection, and ingestion API to remain unchanged, so that a visual redesign does not alter the research job itself.

## Implementation Decisions

- The change applies only to the active post-submit Deep Research workspace. The idle composer, collection validation, query submission behavior, and Knowledge Base surface remain unchanged.
- The compact global navigation shell remains. “Fullscreen” means one research surface in the content area, not removal of the application escape routes.
- The existing SSE wire contract, research lifecycle, source ranking, source reconciliation, source selection, cancellation, and ingestion behavior remain the system contracts.
- The highest new seam is a feature-local normalized trace projection consumed by the route view. Existing raw-event interpretation should be centralized there rather than duplicated in the route, timeline, and run controller. This preserves the direction of the existing trace-projection work.
- The projection remains pure and in-process. It normalizes brief/sketch aliases, query plans, supervisor iterations, query-result batches, source discoveries, scoring, terminal events, errors, and unknown events. It does not own React state, network I/O, source selection sets, ingestion, cancellation, or SVG coordinates.
- The run controller remains responsible for ephemeral lifecycle state, stale-run rejection, AbortController cancellation, elapsed time, source selection/deselection memory, final source reconciliation, and ingestion outcomes.
- The route view consumes normalized facts and derives a semantic ordered route. It does not inspect raw parent-linking rules or independently pair lifecycle events.
- The query header is rendered with the existing calling-card renderer. The visual artwork is generated once per query and reused through live updates. Long queries are split into a small number of readable lines, with a semantic full-text equivalent retained in the DOM.
- The Brief + Sketch milestone is visible immediately as a pending state. Its artifact rows resolve independently when the brief event provides the corresponding data.
- Artifact popovers show useful summary fields: the scoped brief with query plan/tools, and sketch concepts, discriminative terms, expected patterns, and preferred domains. Raw reasoning remains omitted from the compact popover unless the existing data presentation requires a future explicit expansion.
- Supervisor checkpoints are compact, noninteractive spine markers: one per iteration plus one final Evidence ranked marker. They are not full source cards and do not create additional permanent panes.
- Each checkpoint owns a fan-out of one pending query-result node per planned query. A query-result node resolves to the number of newly added canonical URLs, zero sources, or a failed outcome. It displays compact tool and shortened-query context and is not interactive.
- New queries discovered after the initial plan append in trace/event order. The layout does not reinsert historical nodes or visibly reflow completed route history.
- The final route converges at Evidence ranked and then Ingest Sources. The final node is locked until the ranked, deduplicated final source list is available.
- The source list uses the existing selection logic: default selection of new sources, explicit deselection persistence, select all/deselect all, individual checkboxes, source links, selected counts, and existing import outcomes.
- The source list opens in a true modal with an accessible name, focus containment, Escape and close controls, and focus return to the Ingest Sources action. On narrow screens artifact popovers use an anchored presentation when possible and fall back to a bottom-sheet/full-width dialog when needed.
- Connectors are deterministic SVG paths behind semantic DOM content. They use fixed multi-segment jagged geometry rather than random animation or a physics layout. Completed and pending geometry is black; the active segment may use a restrained red accent; errors and completion use text/markers as well as color.
- The route uses angular black cards with red offsets and white/red typography. Existing project fonts, tokens, and assets may be reused; no new reference artwork, downloaded font, graph library, canvas route layer, or dependency is added.
- Desktop uses a vertically scrollable zig-zag/fan-out composition. Mobile collapses branches into a vertical sequence. There is no horizontal trace scrolling, pan, zoom, minimap, or fullscreen toggle.
- Status, elapsed time, Cancel, and New Research remain in a compact route header outside the process nodes.
- Draw-on and active-state motion is disabled under `prefers-reduced-motion`, while the same completed, active, pending, and failed states remain visible immediately.
- Source nodes are display-only. The only route actions are the two artifact rows and the final Ingest Sources action, which keeps the keyboard path short and intentional.
- No sidecar algorithm, request schema, SSE field, ranking rule, collection contract, or ingestion endpoint is changed for this presentation redesign.

## Testing Decisions

- Tests should assert observable route behavior and accessibility outcomes rather than CSS class names, private maps, helper names, SVG coordinates, or the number of React components.
- The primary seam is the normalized trace projection and its semantic route output. A deterministic fixture runner should cover the projection through its public input/output boundary.
- Projection fixtures should cover pending and completed brief/sketch data, snake_case and camelCase aliases, planned query batches, multiple supervisor iterations, newly appended queries, duplicate URLs, zero-result batches, failed batches, ranked completion, partial terminal results, unknown events, and arrival-order preservation.
- Route behavior tests should verify the requested node ordering, checkpoint ownership of query branches, status transitions, unique-source counts, error retention, locked/unlocked ingestion, and absence of timestamp-based reordering.
- Source-state tests should reuse the existing pure selection helpers and cover canonical URL deduplication, new-source auto-selection, explicit deselection persistence, final ranked reconciliation, select all/deselect all, zero selection, full import, partial import, and total failure.
- Modal and popover tests should verify accessible names, close behavior, Escape handling, focus containment, focus return, mobile fallback semantics, and preservation of source controls.
- Accessibility tests should verify semantic landmarks, ordered DOM route order, only action elements in the tab sequence, live status announcements, non-color state cues, visible focus, and reduced-motion behavior.
- Responsive tests should verify the desktop fan-out, vertical page scrolling for many nodes, mobile branch collapse, wrapped query handling, no horizontal overflow, and no clipped popover/modal content.
- Visual verification should use the existing browser verification practice for the Deep Research surface at desktop and narrow widths, including live progress, a multi-iteration run, zero-result and failed searches, timeout/failure, successful import, partial import, cancellation, and New Research.
- Existing Deep Research frontend and route regression checks remain the integration-level prior art. The new projection fixture runner is the focused behavior seam; static checks should be limited to wiring, accessibility, and absence of duplicate raw-event interpretation.
- Verification should include the existing frontend lint/build and diff checks. No unrelated Knowledge Base or API cleanup is required to complete this feature.

## Out of Scope

- Redesigning the idle research composer.
- Redesigning Knowledge Base, collection management, or the global navigation shell beyond the compact active-run controls needed by this surface.
- Changing research ranking, supervisor decisions, query decomposition, search tools, iteration limits, stopping behavior, or source scoring.
- Changing the SSE wire contract, request schema, sidecar behavior, ingestion endpoint, collection behavior, or cancellation semantics.
- Adding research history, saved runs, persistence, authentication, multi-user behavior, or resumable sessions.
- Adding a synthesized research answer or conversational dialogue flow.
- Adding user-selectable tools, research modes, filters, or editable brief/sketch data.
- Adding source-node detail popovers, source-batch filtering, or source selection directly from individual batch nodes.
- Adding route pan, zoom, minimap, horizontal canvas scrolling, fullscreen toggles, draggable nodes, physics layout, or a graph visualization dependency.
- Rendering every raw supervisor/tool/scoring event as a full-size node. Only the agreed compact checkpoints and query-result nodes are visible in the primary route.
- Offering partial unranked ingestion after a failed or timed-out research run.
- Adding new Persona/reference artwork, downloaded fonts, external asset dependencies, or proprietary game UI replicas.
- Broad global typography, theme, or design-system changes.

## Further Notes

- This spec supersedes the four-pane presentation direction in the earlier Deep Research route-map issue while retaining its contract-preservation and accessibility requirements.
- The existing trace-projection effort remains the preferred data seam. The visual redesign should consume that seam rather than reintroduce raw-event interpretation into multiple views.
- The owner confirmed the core seam and interaction decisions during design grilling: preserve the existing data/selection seam, replace the active views, and keep the redesign scoped to the post-submit workspace.
- The implementation branch is `design/research-trace-grill`. This planning change should not modify unrelated working-tree changes.
